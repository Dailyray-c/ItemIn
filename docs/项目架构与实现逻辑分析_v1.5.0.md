## 2. 技术栈与运行时拓扑

- **Vue 3.5.42**，`vendor/vue.global.prod.js` 本地加载（含运行时编译器 —— 模板是 **in-DOM 模板**，不是 SFC）
- **无构建框架**：无 SFC、无打包器、无路由、无状态库、无 TypeScript
- **TailwindCSS 3.4.19**：只在开发期把 `src/tailwind.css` + `tailwind.config.js` 编译成 `styles.css`，运行时零依赖
- **PWA**：`service-worker.js` + `manifest.json` + 三档图标
- **云同步**：Upstash Redis REST（单文档 `itemin:sync`，gzip + base64 信封；与上游 FoodIn 的 `foodin:sync` 键隔离，配置同源）
- **扫码/二维码**：`html5-qrcode` / `qrcode` 两个 vendor 库，**按需注入**，不进首屏

```
浏览器
 └─ index.html
     ├─ <head>  window.ITEMIN_V → JS 动态创建 6 个 ?v= 资源链接
     ├─ <style>①  :root 令牌 + .fi-* 组件类
     ├─ <link>    styles.css（Tailwind 工具类）
     ├─ <style>②  fontScale 三档覆盖（标准 / 大 / 超大）
     ├─ 模板     8 个 currentPage 区块 + 弹层 + 导览蒙层
     └─ <script> createApp → setup() → return{} → mount → 注册 SW
```

## 5. 页面与导航模型

**没有路由**：全文件 0 处 `history.pushState` / `location.hash` / `popstate`。页面由 `v-if="currentPage === 'xxx'"` 整块挂载/卸载。

- 唯一页面状态：`currentPage = ref('home')`（4249）+ `cameFromGuide`（4336）
- 切换入口：`navigateTo(pageId)`（**4997**）
- `pages` computed（4873）：简洁模式 3 项（首页/录入/我的），正常 5 项（首页/扫码/记录/统计/设置）
- 导航高亮：`batch` 归属 `scan`；`guide` 与 `settingsAdvanced` 归属 `settings`；简洁模式下 `records`/`stats` 也归属 `settings`

**模块色（v1.4.0）**：`MODULE_OF_PAGE`（页面 → 模块）+ `MODULE_STYLE`（模块 → 三条类名字面量）
是导航与页头配色的唯一真源，归属与 `isNavActive()` 完全一致，所以高亮永远不会和页头对不上。

| 模块 | 色 | Tailwind | 覆盖页面 |
|---|---|---|---|
| 首页 | 木纹棕（主色） | `mod-home` = `brand` | `home` |
| 录入 | 松花 | `mod-scan` | `scan` / `batch` |
| 记录 | 天水碧 | `mod-records` | `records` |
| 统计 | 靛青 | `mod-stats` | `stats` |
| 设置 | 藕荷 | `mod-settings` | `settings` / `guide` / `settingsAdvanced` |

- ❗类名必须写**完整字面量**（`'bg-mod-' + id` 会被 Tailwind 扫描静默丢弃）
- ❗模块色只上导航与页头；**控件仍一律 `brand`**

## 6. 数据模型

### 6.1 product（商品）

构造点 5 处，**新增字段时全部要改**：`submitProduct`(7718)、`submitBatchItem`、`seedDemoData`(7283)、`executeRevoke` 快照重建、降级重建。

| 字段 | 类型 | 说明 | 空值 |
|---|---|---|---|
| `id` | string | `crypto.randomUUID()`，降级为 `Date.now().toString(36)+rand`（`generateId` 5839） | — |
| `name` | string | 提交前过名称清洗 | 必填 |
| `barcode` | string | 条码 | `''` |
| `location` | string | ⚠️ **逗号字符串**（`, ` 分隔），表单态是**数组** | `''` |
| `category` | string | 同上 | `''` |
| `stockInDate` | string | `YYYY-MM-DD`，默认本地今天 | 今天 |
| `productionDate` | string | 生产日期 | `''` |
| `shelfLife` | string | **文本**，如 `"12个月"`；历史纯数字按「天」解释 | `''` |
| `expiryDate` | string | 到期日 | `''` |
| `expiryKind` | string | `保质期 \| 保修 \| 更换 \| 归还`（`EXPIRY_KINDS` 4276） | `'保质期'` |
| `quantity` | number | **当前剩余件数** | 1 |
| `minQty` | number \| `''` | 补货线；`''` = 不提醒 | `''` |
| `brand` / `spec` / `netContent` / `manufacturer` | string | 品牌 / 规格 / 净含量 / 厂家 | `''` |
| `price` | number \| `''` | ⚠️ **多件总价，不是单价**；`''` ≠ 0 | `''` |
| `imageUrl` / `note` | string | 图片链接 / 备注 | `''` |
| `createdAt` / `updatedAt` | string | ISO 时间戳 | now |
| `__demo__` | boolean | 导览示例标记，同步引擎完全剔除 | 仅示例 |

**不变量**：
1. 一个 SKU = **一个对象**，数量存在 `quantity`，**绝不往数组塞多条**；不存在 `qty`/`count` 字段。
2. 数量归零即**移除对象**（`removeProduct` 6892），库里不存在 `quantity: 0` 的滞留项。
3. `location` / `category` 落库前必须走 `normalizeProductList` → 「去空白 + 去空 + 字段内去重 + `, ` 拼接」。**不要把数组写进商品**。

### 6.2 record（流水）

**唯一构造入口**：`addRecord(data)`（**6381**），返回新记录，供调用方关联撤销快照。禁止在别处 `records.value.push`。

| 字段 | 说明 |
|---|---|
| `id` | 主键，也是撤销快照的 key |
| `type` | `in \| eat \| waste \| adjust \| borrow \| return` |
| `productId` | 关联商品 id，可为 `''` |
| `productName` / `barcode` | **快照**（商品删了流水仍可读） |
| `quantity` | 带符号件数：`in` 正、`eat`/`waste` 负、`adjust` 0 |
| `detail` | ⚠️ **格式是契约**：`字段label：before → after`，多段用 `·` 分隔。撤销的字段反推依赖它 |
| `unitPrice` | **单件单价快照** = `price / quantity`，2 位小数 |
| `netContent` | 净含量快照 |
| `reason` | 浪费原因枚举 **value**（非中文）：`stale \| spoiled \| tired \| overbought \| other` |
| `borrower` | 借出 / 归还对象（未填 = `'未记名'`） |
| `createdAt` | **唯一时间戳**：筛选、按天分组、趋势全部基于它 |
| `__demo__` | 示例标记 |

**六种类型与触发点**

| type | 界面标签 | quantity | detail 示例 | 触发函数 |
|---|---|---|---|---|
| `in` | 入库 | 正 | `新增入库 +3` | `submitProduct` / `submitBatchItem` / `incrementStock` |
| `eat` | 取出 | 负 | `正常取出 -1` | `eatOne`（6822） |
| `waste` | 浪费 | 负 | `删除商品，浪费 3 件（放过期了）` | `executeWasteDeleteWithReason`（7409） |
| `adjust` | 调整 | 0 | `分类：食品 → 日用品 · 价格：5 → 8` | `saveEdit` / 数量直改 |
| `borrow` | 借出 | 负 | `借出 1 件（张三）` | `confirmBorrow` |
| `return` | 归还 | 正 | `归还 1 件（张三）` | `returnBorrowed`（7046） |

改 `type` 或新增类型必须同步**四张映射**：`recordBadgeClass`(6281)、`recordNumberClass`(6284)、`recordTypeLabel`(6287)、`recordBarColor`(6290)，以及 `recordTypeOptions`(4721)、`QTY_RECORD_TYPES`(5651)、`revokePreview`(6625)、`executeRevoke`(6690) 的分支。

### 6.3 settings

**全文件唯一默认值**：`const settings = reactive({...})`（**4277**）。没有 `DEFAULT_SETTINGS` 常量。

| 类别 | 字段 |
|---|---|
| **进云同步（`SETTINGS_SYNC_SCHEMA` 9 项）** | `expiringDays` `categories` `places` `nameCleanEnabled` `nameCleanCase` `nameCleanMarketing` `nameCleanCustom` `nameCleanWhitelist` `fontScale` |
| **本机专属（刻意不同步）** | `version` `cloudApiKey` `cloudBinId` `cloudSyncEnabled` `cloudLastSync` `localModified` `barcodeApiKey` `barcodeLookupEnabled` `autoSaveInterval` `simpleMode` `tourDone` `demoKept` |

> ❗`settings.version` 初始化为 `CURRENT_VERSION` 且启动时会被覆盖 → **它永远等于当前代码版本，不能当迁移判据**。

### 6.4 places（地点 → 分区，两级）

```json
{ "name": "冰箱", "zones": ["冷藏", "冷冻"], "partitioned": true, "layout": "" }
```

- `zones` 是**字符串数组**，不是 `[{name}]`
- `layout` 是表单临时态；上云前由 `placeSyncCopy()` 剔除
- **`location` 实际存的是「一个位置标签」**：可能是地点名、分区名，或不属于任何地点的独立标签
- **按地点批量操作的唯一正确判据**：`loc === place.name || place.zones.includes(loc)`
- **删地点 ≠ 改地点**：删 → 命中商品 `location` **一律清空**；改 → **只改「存地点名」那批**，分区商品不动
- `settings.locations` **已废弃**，唯一真源是 `places`；`migrateLooseLocationsToPlaces()`（8920）仅用于兼容旧数据

### 6.5 撤销快照（仅本机）

`localStorage['itemin_undo_cache']`，**不进云、不进 record、不进 `SETTINGS_SYNC_SCHEMA`**。

```js
undoCache[recordId] = { product: <变更前完整深拷贝>, at: ISO, changed: ['category','price'] | null }
```

上限 **300 条** / TTL **60 天** / 孤儿自动清理（`pruneUndoCache` 6352）。

### 7.1 `saveData()`（6376）—— 唯一常规写入口

```js
products.value = normalizeProductList(products.value);   // 必须在 diffToEvents 之前
normalizeSettingsCollections();
settings.localModified = new Date().toISOString();
try { 写 4 个键 } catch { toastErr('本地保存', '浏览器存储空间不足或被禁用'); }
if (云同步已配置) { diffToEvents(); 15s 防抖 → cloudSync(false); }
```

- ❗**`saveData()` 本身无节流**：每次全量 `JSON.stringify` 三个大对象；唯一的写侧防抖是**云推送 15 秒**
- 批量录入 `submitBatchItem` 每条都调 `saveData()` → N 条 = N 次全量写
- **绕过 `saveData()` 的直写点 3 处**：重复 id 自愈（去重落盘）、云同步重放、幽灵商品清理。新增直写前必须确认不会破坏差分基线

### 7.2 `loadData()`（6396）—— 逐键隔离

- 每个键独立 `readKey`，解析失败时**原始字符串先复制到 `<key>__corrupt_<时间戳>`** 再移除原键，**绝不静默清空**
- 归一化与迁移单独 `try/catch`，不影响已成功读取的数据
- 有键损坏时 `toastErr('读取本地数据', '部分数据损坏，已隔离备份')`
- **没有版本号迁移框架**：全是「字段缺失即补默认」的幂等内联补丁

### 7.3 键前缀与一次性迁移（`LS_PREFIX`）

- **所有键必须经 `lsKey(name)` 生成**，禁止再写字面量 —— 散落的字面量正是前缀隔离漏改的原因
- 当前前缀 `itemin_`；旧前缀 `food_inventory_` 仅用于迁移读取（`LEGACY_LS_PREFIX`）
- `migrateLocalStoragePrefix()` 在 `onMounted` **第一步**执行（早于 `loadData` / `initSyncEngine` / `loadUndoCache`）：
  - 逐键 `旧键有值 && 新键为空 → 复制`；**绝不覆盖**已有新键
  - 迁 `products` / `records` / `settings` / `barcode_cache` / `undo_cache` / `sync_v2` 六个键。`sync_v2` 必须迁，否则设备 id、墓碑 `knownIds`、待推队列全部丢失
  - 成功写标记 `itemin_prefix_migrated`：**防止用户清空数据后旧键被搬回来**（清了又回来）
  - 有键失败（配额满/被禁用）则**不写标记**，下次启动重试
  - **旧键一律不删**：既是回滚到旧版本的唯一样本，也是失败兜底；确认无碍后可手动清理
- 迁移必须在 `loadData()` 之前：放在之后会读到空库，并被随后的 `saveData()` 写回空值（永久丢数据）

## 8. 核心业务流程

### 8.1 录入（scan）

`submitProduct`（7718）：校验 → 日期合法性（生产日期 ≤ 今天、到期 ≥ 生产）→ 名称清洗 → 构造 product → `products.push` → `addRecord({type:'in'})` → 写条码缓存 → `saveData()` → toast → 重置表单并收起「日期信息」。

- 表单字段见 `scanForm`（4886）；`location`/`category` 在表单里是**数组**
- 「日期信息」三字段（生产 / 保质期 / 到期）**任填两项自动算第三项**，**全部选填**（v1.1.0 起取消了「至少填两项」校验）

### 8.2 库存增减

| 入口 | 函数 | 说明 |
|---|---|---|
| `+1` 按钮 | `incrementStock`（6807） | 发 `in` 流水 |
| `-1` 按钮 | `decrementStock`（6815）→ 二次确认 → `eatOne`（6822） | 确认后才写 `eat` 流水；归零自动移出库存 |
| 数量圆点击 | `openQtyPrompt` / `confirmQtyPrompt`（6796/6801） | 生成一条 `adjust` 流水，可撤销 |
| 借出 | 借出弹窗 | 记 `borrow`，`quantity` 减少，写 `borrower` |
| 归还 | `returnBorrowed`（7046） | 记 `return`，`quantity` 增加 |

**借出未还完全由流水推导**：`borrowedQtyOf`（6929）= `borrow` 合计 − `return` 合计 > 0。**没有状态位**，因此天然支持撤销。

### 8.3 删除与浪费

- `confirmDelete`（7387）→ `executeDelete`（7392）：还有库存时必须选浪费原因
- `executeWasteDeleteWithReason`（7409）：写 `waste` 流水（负数）→ 移除商品
- 浪费原因中文映射见 `WASTE_REASONS`（4342）；`tired` 的显示值是**「用不上了」**（不是「吃腻了」）

### 8.4 编辑（edit）

`saveEdit`（7535）：
1. 逐字段比较，收集 `changes` 列表
2. 只在 `editForm._slTouched === true` 时重算 `shelfLife` 文本（防止「无操作重写」凭空生成调整记录）
3. 有变化才写 `adjust` 流水 + `saveUndoSnapshot(record.id, 变更前快照, changedKeys)`

### 8.5 撤销（revoke）

`revokePreview`（6491，computed）→ `executeRevoke`（6690）。

三层降级：
1. **本机快照 = 天然边界**：别的设备建的流水在本机没有快照 → 走旧逻辑，别人的数据保持原状
2. **字段级回退**（`changed`）：只回填本条实际改过的字段
3. **从 `detail` 反推**：按 `·` 切段 → 取 `：` 前的 label → 经 `UNDO_KEY_BY_LABEL` 映射回字段名

**数量的特殊规则**：一律走 **delta 反向**，不用快照绝对值（同一商品可能有多条同类流水）。`eat`/`waste` 且商品仍在库 → 只「补空」不覆盖；商品已被移出 → 完整重建。

### 8.6 导入 / 导出

| 功能 | 函数 | 备注 |
|---|---|---|
| 全量备份导出 | `exportData`（8187） | JSON |
| 备份导入 | `importData`（8204） | 按 id 合并，不覆盖本地。**云同步凭据 / `cloudSyncEnabled` / `barcodeApiKey` 不从备份恢复**（导入前会备份指向别人的 bin，空值还会静默关掉本机同步）；导入后若本机已配过云端，会**立即** `diffToEvents()` 落事件（不等同步开关），避免「关了同步时导入 → 之后重新打开 → 导入内容推不上去还被云端覆盖」 |
| 清空全部 | `clearAllData`（8322） | 危险操作，不可撤销 |
| 库存 CSV | `exportStockCsv`（8384） | |
| 流水 CSV | `exportRecordsCsv`（8420） | |
| 统计 CSV | `exportStatsCsv`（8437） | |

### 8.7 扫码与条码查询

- `ensureScanLib`（7864）：单例 Promise + 多源回退（vendor → unpkg → jsdelivr），失败清空可重试
- `openScan(context, targetItem)`（7658）：**必须 `await`**，失败时关弹层 + `toastErr`，不留黑屏取景框
- `lookupBarcode`（8072）：本地缓存优先 → 三级 API 回退（apizero GS1 → apizero 查询 → Open Food Facts）；**任何失败都不阻塞录入**
- 只有以 `69` 开头的国内 GS1 条码才自动查 API，其余提示手填

### 8.8 示例数据与导览

- `DEMO_MARK = '__demo__'`（7037）：示例商品 / 流水必须对**云同步引擎完全不可见**（`captureState` 过滤 + `applyStockDelta` 直接 return）
- `settings.demoKept` 是本机字段：用户主动「载入示例」后，启动兜底清理不再删除
- `TOUR_STEPS`（5148）数据驱动，9 步跨五页；加步骤只加一行

## 9. 云同步子系统

**定位**：事件溯源语义 + 单文档物理存储（拉整份 → 内存合并 → 整份覆盖写）。没有用 Redis 的 append 结构。

### 9.1 后端与协议

| 动作 | 请求 |
|---|---|
| 读 | `GET {REST_URL}/get/itemin%3Async`，`Authorization: Bearer {token}` |
| 写 | `POST {REST_URL}/set/itemin%3Async`，值走 body，`Content-Type: text/plain` |

- 文档键 `CLOUD_DOC_KEY = APP_SYNC_NS + ':sync'`（9721，`APP_SYNC_NS = 'itemin'`）→ 实际值 **`itemin:sync`**
- ❗**命名空间隔离（v1.5.0）**：上游 FoodIn 写的是 `foodin:sync`。两边共用同一份配置（同一个 REST URL + Token、
  同一个库、同一套额度），但**文档键不同** → 各写各的键、各读各的键，事件不会互相重放。
  这是「互串数据」的唯一根因，改键就等于隔离，**不要**改回 `foodin:sync`。
- `LEGACY_CLOUD_DOC_KEY = 'foodin:sync'`（9724）**只读**，只用于换键过渡时的文案与判定，任何写入路径都不得使用
- 换键守卫在 `initSyncEngine()`：`syncState.docKey !== CLOUD_DOC_KEY` 时把 `baseState` 置空 + 水位/回读标记归零
  → 首轮差分把本机全量当「新增」入队，新文档由本机数据初始化（**不**从旧键搬，旧键里两边数据已混在一起）
- `settings.cloudBinId` = **REST URL**，`settings.cloudApiKey` = **REST Token**（字段名沿用历史，**不要改名**）
- 两者都是**本机专属**，不进 `SETTINGS_SYNC_SCHEMA`
- 负载必须走 body，**绝不能拼进 URL**（gzip 后仍数十 KB）

### 9.2 文档结构

```json
// 内层
{ "schemaVersion": 2, "syncedAt": "...", "events": [ /* ≤30 */ ],
  "snapshot": { "products": [], "records": [], "settings": {},
                "upToId": "dev-xxx:v4w8:511", "knownIds": ["record:...", "..."] },
  "barcodeCache": {} }

// 外层（支持 CompressionStream 时）
{ "schemaVersion": 3, "compressed": true, "algo": "gzip", "data": "<base64>" }
```

### 9.3 事件

```json
{ "id": "dev-mu18:5j51:489", "ts": "2026-09-20T12:01:39.952Z",
  "kind": "product", "op": "delta", "key": "pmu9mfzcc528sdp",
  "patch": { "delta": -1, "quantity": 1 } }
```

- `id` = `deviceId + ':' + tabNonce + ':' + lastSeq` —— **格式是跨设备去重的唯一基础，不可改**
- `ts` 是 Lamport 式水位；`eventOrder` 先 `ts` 升序、再按 `id` 字典序 → 全系统单一全序
- `op`：`upsert` / `delta` / `delete`；`delta` **必须恰好一次**（应用两次会导致数量双计）
- 冲突：product/record 字段级 LWW；`quantity` 走 delta 累加（下限 0）；setting 整值覆盖

### 9.4 两条写入通道

1. `diffToEvents`（9497）：`captureState()` vs `syncState.baseState` 差分 → 逐字段 `fieldPatch`；缺失 id 发 delete
2. `applyStockDelta`（9550）→ `emitStockDelta`（9537）：数量变更的独立通道；**必须同步把 `baseState` 里该商品 `quantity` 改成结果值**，否则下轮 diff 会再发绝对值 upsert 造成双计

### 9.5 折叠

`events.length > 30` → 保留最后 20 条，其余折叠进 `snapshot`，`upToId` 取最后一条事件 id，实体 id 累进 `knownIds`。

### 9.6 主流程与铁律

`cloudSync(showMsg)`（**9681**）：

```
拉取 → 失败? → 直接 return（不推送）
     → 成功 → 重放合并 → 有变更? → 推送 → 回读校验 → 清空已确认队列
```

- ❗**铁律：先拉取，拉不到绝不下发**。服务端故障时云端不会被覆盖，待推事件留在本地，恢复后补推
- **重入保护**：`syncInFlight` 期间返回 `{ok:false, skipped:true}`
- **失败退避**：30s 起、每次 ×2、封顶 5 分钟；成功复位
- **触发时机**：本地变更 15s 防抖 / 自动云保存（默认关）/ 启动（有 pending 或距上次 ≥10 分钟）/ 断网恢复 / 回到前台（≥2 分钟）/ 手动 / 配置码接入

### 9.7 设置同步 schema（接口定义）

```js
{ key, type: 'number'|'array'|'bool'|'string', default, mode?: 'replace'|'union'|'localFirst', values?, allowEmpty? }
```

- 驱动 6 处：`captureState` / `diffToEvents` / `replayState` 初始化 / 重放应用 / guarded 补推 / `applyLegacyUnion`
- `number` 用 `!!v` 排除 0；`string` 非 `allowEmpty` 排除空串；`values` 是白名单
- ❗**空数组是合法值**（支持「清空全部地点」传播）
- ❗**空串必须显式 `allowEmpty: true`**，否则「清空后再也同步不出去 / 拉不回来」

## 10. 对外接口

### 10.1 `return {}`（模板白名单，10340）

模板能访问的一切都必须在 `return {}` 里。漏登记有两种面孔：

| 漏掉的是 | 现象 | 典型 |
|---|---|---|
| 副作用函数（`saveData` / `toastDone`） | UI 正常但**不落盘 / 无 toast**，刷新回滚 | 模板里 `settings.x = v; saveData()`，赋值先于抛错执行 |
| **处理器本身**（`toggleCategory`） | 控制台 `TypeError: xxx is not a function`，按钮点了完全没反应 | 每次点击报一次，页面加载时无异常 |

核对方法：模板区（`id="app"` 到 app 脚本之间）`{{ }}` 与 `:x=` / `@x=` 值里出现的 `name(`，
减去 setup 里 `function name` / `const name =` 的定义集，**差集必须为空**。
v1.4.0 曾漏掉 `toggleCategory`（录入 / 批量录入 / 编辑三处「分类」按钮全废），就是这条没自查。

### 10.2 `window.__itemin`（自动化白名单，10332）

E2E 脚本可达的 API 子集。**不是 `return {}` 的超集**，两份都要手工维护。

常用接口：

| 接口 | 说明 |
|---|---|
| `navigateTo(pageId)` | 切页（**没有 `add` 页**，录入走 `scan`） |
| `currentPage` | ref |
| `products` / `records` / `settings` | ref / reactive |
| `saveData()` / `cloudSync(showMsg)` | 手动落盘 / 同步 |
| `applyStockDelta(product, delta)` | 数量变更（含事件） |
| `executeRevoke()` / `revokePreview` | 撤销 |
| `seedDemoData()` / `clearDemoData()` / `endTour()` | 导览相关 |
| `setShowScanModal(v)` / `setShowFilterModal(v)` | ❗这两个是 setter；`showScanModal()` 是 getter，**不能 `.value =`** |

**核对方式**：判断标识符是否在白名单里必须用正则 `(?<![\w$])name(?=\s*[,}])`，用 `in` 会被尾逗号骗过。

### 10.3 全局组件

`<toggle-setting v-model="x" color="brand">` —— `app.component('toggle-setting', ToggleSetting)`（10112），render 函数定义，**开关的唯一合法写法**。

## 11. 构建与离线

### 11.1 构建

```bash
npm run build:css    # tailwindcss -i ./src/tailwind.css -o ./styles.css --minify
```

- 只有**新增从未出现过的 utility class** 才需要重编译
- 改 `.fi-*` 组件类 / JS 逻辑 / 模板条件**不需要**
- 漏编译症状：功能全对，样式失效或高度塌陷为 0（按钮点不到）
- 校验某个类是否进 CSS 必须 `grep -o 'lg\:mt-auto'`（`grep -c` 因 minified 单行永远返回 1）

### 11.2 Service Worker

- 白名单模式：非 GET 放行；跨域放行；只有**同源 GET** 进入缓存逻辑
- 导航请求网络优先；静态资源 cache-first + 后台 revalidate
- 预缓存 `Promise.allSettled` 逐资源，失败点名日志
- 静态资源回源失败返回 **504**，**不伪造首页 HTML**
- `activate` 只清**自身前缀** `item-inventory-` 的旧缓存
- ❗改动 `index.html` / `styles.css` / `service-worker.js` / `vendor/` 任一项 → **必须 bump `CACHE_NAME`**

### 11.3 缓存隔离（`?v=` 机制）

- 本应用与上游 FoodIn 都用 8088 端口 → 同源、同名、不同内容
- `styles.css` / `manifest.json` / 图标全部带 `?v=<ITEMIN_V>`
- ❗**不要改回「静态 href + JS 改写」**（会先请求一次旧 URL）
- ❗**不要在 SW 里剥掉 `?v=`**（会命中预缓存里的旧文件）
- 发版需同步两处静态副本：`manifest.json` 的 3 个图标地址、`service-worker.js` 的 `PRECACHE_ASSETS`

## 13. 术语表（消除歧义）

| 术语 | 精确定义 | 易混点 |
|---|---|---|
| **物品 / 商品** | `product` 对象，一个 SKU 一条 | 不是「一件」，一件是 `quantity` |
| **入库** | `type='in'` 的流水 | 与「新增商品」同一次操作产生 |
| **取出** | `type='eat'` 的流水（旧名「吃完」「消耗」） | **不是**「消耗」；「消耗」已废止 |
| **浪费** | `type='waste'`，删除仍有库存的商品时产生 | 与「取出」互斥，不重复计数 |
| **调整** | `type='adjust'`，数量直改或编辑属性 | `quantity` 为 0 |
| **借出 / 归还** | `type='borrow' / 'return'` 的**流水** | ⚠️ 与「到期类型·归还」不是一回事 |
| **到期类型·归还** | `product.expiryKind = '归还'`，表示该物品本身要在某日前还回去 | ⚠️ 与流水 `return` 同名不同义 |
| **地点** | `places[].name`，如「冰箱」 | |
| **分区** | `places[].zones[]`，如「冷藏」 | `location` 存的是分区名**或**地点名**或**独立标签 |
| **待归位** | `location` 为空的商品 | 不是「未分类」 |
| **补货线** | `product.minQty`，低于即进「待补货」 | 留空 = 不提醒，`0` 是有效值 |
| **撤销** | 删除该条流水并回滚其影响 | 与「删除商品」不同 |
| **不落盘** | 内存状态正确但没写进 localStorage，刷新即回滚 | 典型原因：函数漏出 `return {}` |
| **示例数据** | 带 `__demo__` 标记、导览专用、对云同步不可见 | 不是普通用户数据 |

## 14. 改数据结构的连带改动清单

### A. 新增 product 字段

1. 构造点 5 处：`submitProduct`(7718) / `submitBatchItem` / `seedDemoData`(7283) / `executeRevoke` 两条重建分支
2. 表单 3 处：`scanForm`(4886) / `editForm`(4911) / `blankBatchItem`(4925)
3. `saveEdit` 的 `changes.push` 列表**和**赋值段要**成对**加

5. CSV 导出表头 + 行：`exportStockCsv`(8384)

> 云同步**无需登记**（`captureState` 全量 + `fieldPatch` 动态）。但**删字段/改字段名不会生成补丁**（`fieldPatch` 只遍历 live key）→ 云端旧值会残留并在下次重放时复活。删字段必须显式发一次全量 upsert 或做兼容读。

### B. 新增 settings 字段

1. 默认值加进 `settings = reactive({...})`(4277)

5. 枚举型 → 在 `loadData` 加校验（参考 `fontScale`）
6. 密钥 / 本机地址 → **明确不加 schema，并写注释说明原因**

### C. 新增 record 类型

1. `addRecord`(6465) 调用点
2. 四张映射：`recordBadgeClass` / `recordNumberClass` / `recordTypeLabel` / `recordBarColor`

5. `exportRecordsCsv`(8420)
6. `revokePreview`(6625) + `executeRevoke`(6690) 加分支 —— **漏了会导致撤销按钮静默消失**
7. `detail` 格式是契约，改它必须同步改 `undoChangedFromDetail`(6592)

### D. 新增页面
