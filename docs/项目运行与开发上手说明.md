## 3. 环境准备

依赖已随仓库带入（`node_modules/` 存在）。需要重装时：

```bash
npm install
npx playwright install chromium
```

本机实测的托管运行时（**按当前机器填写，不要照抄到别的机器**）：

| 运行时 | 路径 | 用途 |
|---|---|---|
| Node | `C:\Users\Workbuddy\.workbuddy\binaries\node\versions\22.22.2-6\node.exe` | Tailwind 编译、Playwright |
| Python | `C:\Users\Workbuddy\.workbuddy\binaries\python\versions\3.13.12\python.exe` | 本地静态服务（`scripts/` 已于 2026-10-17 移除） |

### Windows 环境四个坑

1. **调 Playwright 用 PowerShell**：bash 里跑 node 可能以退出码 23 结束且**无输出**。路径写 `C:/…` 盘符形式。
2. **不要设 `PLAYWRIGHT_BROWSERS_PATH`**（MSYS 会转义坏，导致找不到浏览器）。
3. **Git Bash 报 `ls: command not found`**：路径被打断，用完整 `export PATH=...:$PATH` 补齐。
4. **`http.server` 是单线程**：并发请求会排队，批量截图时注意别同时打多路。

## 4. 本地运行

```bash
start_service.bat                      # = python -m http.server 8088 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8088/
```

| 场景 | 端口 | 地址写法 |
|---|---|---|
| 日常预览 | **8088** | `http://127.0.0.1:8088/` |
| E2E 脚本 | **8777** | `http://localhost:8777/`（Playwright 访问 `127.0.0.1` 会被 refused） |

❌ **不要直接打开 `index.html`**：`file://` 下 Service Worker / PWA / 跨域全部失效。

> ⚠️ **8088 与上游 FoodIn 撞端口**：两边 `styles.css` / 图标 / manifest 同名不同内容，浏览器与 SW 按 URL 缓存。
> 本应用已对资源加 `?v=<ITEMIN_V>` 做隔离，正常刷新即可拿到新版；顽固残留时用
> DevTools → Application → Storage → **Clear site data**。

## 5. 构建

```bash
npm run build:css
# 等价：./node_modules/.bin/tailwindcss -i ./src/tailwind.css -o ./styles.css --minify
```

| 改动类型 | 需要重编译？ |
|---|---|
| 新增从未出现过的 utility class | ✅ 需要 |
| 改 `.fi-*` 组件类（内联 `<style>`） | ❌ 不需要 |
| 改 JS 逻辑 / 模板条件（类都已存在） | ❌ 不需要 |
| 改 `tailwind.config.js` 色板 | ✅ 需要 |

- 漏编译症状：**功能全对，样式失效或高度塌陷为 0（按钮点不到）**
- 校验某个类是否已进 CSS：`grep -o 'lg\:mt-auto' styles.css`（**不能**用 `grep -c`，minified 只有一行永远返回 1）
- 任意值类在 CSS 里是转义形式：`text-[11px]` → `.text-\[11px\]`

> ❗改动 `index.html` / `styles.css` / `service-worker.js` / `vendor/` 任一项 → **发版时必须 bump `CACHE_NAME`**。

## 7. 开发规范

### 7.1 版本号

- 格式 `X.Y.Z`，三位必填（`1.3` 不合法）
- `X` 仅破坏性变更；`Y` 可发布的功能集群 / 重要优化；`Z` 仅 Bug 修复与小调整
- **纯修 Bug 绝不 bump Y**
- 物品记版本序列自成一系：`1.0.0 = 原 FoodIn 2.37.0`；FoodIn 2.36 及更早保留原号

### 7.2 发版四处联动（顺序固定）

1. 改 `window.ITEMIN_V`
2. `service-worker.js` 的 `CACHE_NAME` 数值 **+1**（与 X.Y.Z 独立计数，每次发版都要 +1）
3. 应用内 changelog 条目 + `docs/CHANGELOG.md`
4. **改完之后**再备份三件套：
   ```bash
   mkdir -p versions/vX.Y.Z
   cp index.html service-worker.js styles.css versions/vX.Y.Z/
   ```

> ❗**为什么必须 bump 完再备份**：先备份会让目录名装的是**上一版**的内容。上游时代因此出现过 3 个
> 「目录名 ≠ 内部版本」的归档，按文档回退会退到错误版本。**判断归档是否正确：打开 `versions/vX.Y.Z/index.html`，
> 确认 `window.ITEMIN_V` 与目录名一致。**

### 7.3 目录与命名

- 调试脚本 / 截图 / 日志**一律 `_` 开头**（`.gitignore` 已屏蔽 `_*.js` `_*.py` `_*.png` `_*.txt` `_*.log` `_*.json` `_*.html`）
- 正式参考文档统一收进 `docs/`；已过期的收进 `docs/archive/`
- 清理 = **移到 `%TEMP%/<项目>-cleanup-<日期>/` 再确认**，不直接删
- `versions/` 是历史档案，**永不删**

### 7.4 单文件开发五条铁律

1. ❗**同文件多 Edit 必须串行**：同一条消息里并发多个 Edit 只有 1 个生效，其余静默丢失
2. ❗**新增函数 / 状态必须同时进两个白名单**：`return {}`（模板能用）与 `window.__itemin`（自动化能测）。
   漏第一个 = **不落盘**；漏第二个 = 测不到
3. ❗**模板里 `@change` 一律显式传参**（`@change="fn(scanForm)"`）—— 无参写法会把 DOM Event 当第一个实参
4. ❗**三处表单结构一致**：`scan` / `batch` / `edit` 弹窗，改一处必须看另两处
5. ❗**改 UI 三件套**：新增 utility → 重编译；utility 收敛成组件类 → 补 fontScale 三档；
   弹层只用 `z-40` / `z-50`（导览子系统例外）

### 7.5 Git 安全铁律

- ❌ **绝不 `git stash` + `git rebase`**（曾被 SIGTERM 打断导致 `.git` 损坏）
- ❌ **禁 `git add .` / `git add -A`**（工作区有大量 `_` 调试产物）
- ✅ 安全流程：`fetch` → `reset --mixed`（不碰工作树）→ `add <明确文件>` → `commit` → `push`

## 8. 发布与部署

### 8.1 前提：接入 remote

本仓库**没有 remote**（已与上游 FoodIn 脱钩）。首次发布前：

```bash
git remote add origin <你的仓库地址>
```

`push-safe.sh` 在无 remote 时会在 fetch 阶段**明确报错退出**——这是保护，不是故障。

### 8.1.1 ⚠️ 首次推送前必读：历史里有过用户数据

`HEAD`（dae2889）里曾提交过 **`backups/inventory-2026-09-*.json` 共 14 份云同步快照**（真实库存数据，
单份约 220KB）。这些文件在当前工作树里**已经删掉了**，但**删除不会从 git 历史里消失** —— 直接把现有
历史推到公开仓库，任何人都能用 `git show <sha>:backups/inventory-2026-09-06.json` 取回。

因此首次推送**推荐走「全新仓库」**：只提交当前工作树，不带历史。

```bash
# 1) 在 GitHub 上新建一个【完全空】的仓库（不要勾 README / .gitignore / license）
# 2) 在本机：用当前工作树重建一个干净仓库（历史清零，文件一个不少）
cd /d/WorkBuddyWorkSpace/ItemIn
mv .git .git.old            # ⚠️ 改名保留（确认推送无误后再删）；只动 .git，工作文件不受影响
git init -b master
git add -A                  # .gitignore 已屏蔽 _dev/、.workbuddy/、node_modules/、backups/
git commit -m "物品记 v1.4.0：古风彩虹配色 + 模块分色 + 首页状态标记"
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin master
```

> 想保留历史就必须先净化（用 `git filter-repo --path backups --invert-paths` 之类），
> 否则别把旧历史推到公开仓库。`.gitignore` 里已补 `backups/`，防止再次误提交。

### 8.1.2 之后每次发版

首次手动推送过之后，远程已有 `master` 分支，`push-safe.sh` 才能正常 fetch 比对，照常用：

```bash
./push-safe.sh     # 常规发版
./push-clean.sh    # 文档整理后（会带上 docs/ 新增文件）
```

另：`push-readme.sh` 第 76 行硬编码了上游地址 `https://github.com/Dailyray-c/FoodIn`，
接入自己的仓库后记得改成自己的地址。

### 8.2 三个脚本怎么选

| 脚本 | 提交范围 | 何时用 |
|---|---|---|
| `push-safe.sh` | 固定白名单 + `versions/` 全量 | **常规发版** |
| `push-clean.sh` | `git add -u` + `docs/` | 文档整理后、**新增文档**后 |
| `push-readme.sh` | 只 `README.md` | 仅补推 README |

三者都：直连 GitHub（清代理）、`FETCH_HEAD` OID 判活、非快进时重新对齐后重演提交、**绝不 rebase**。

> ⚠️ `docs/` 下的**新增**文件不在 `push-safe.sh` 白名单里，必须走 `push-clean.sh` 或手动 `git add docs/`。

### 8.3 部署链路

```
git push → deploy.yml（cp 白名单到 _site/）→ upload-pages-artifact → deploy-pages → GitHub Pages
```

- CI 白名单：`index.html` `styles.css` `service-worker.js` `manifest.json` `icon-180/192/512.png` + `vendor/`
- **新增顶层目录必须同步加 `cp -r <dir> _site/`**
- 三方一致性：**deploy.yml 拷贝清单 ⊇ `PRECACHE_ASSETS` ⊇ 页面 `src="./…"`**
- 改过 SW 后线上需**刷新两次**；Actions 偶发丢 webhook → 手动 Run workflow 兜底
- 可选打标签：`git tag -a vX.Y.Z -m "…" && git push origin vX.Y.Z`

### 8.4 回退

```bash
cp versions/vX.Y.Z/* .            # 三件套整体替换
# 若该版本之后新增过 utility class，还需按该版本重编译 styles.css
```
